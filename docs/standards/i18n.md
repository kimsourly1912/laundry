# Language: English only

← [Docs](../README.md) · Visual rules: [ui.md](./ui.md) · Review: [ui-review-checklist.md](./ui-review-checklist.md)

The app is **English only** ([D36](../decisions.md#d36-english-only-and-cancel-and-copy-for-mistakes), replacing D4 and D6). A shop that wants Khmer gets it **on its slip**: the artwork is made in Khmer (D35), and field labels are free text the platform may write in Khmer. This page covers UI strings, Khmer text that users type, and money and date display.

Status: `@nuxtjs/i18n` stays with **one locale** (`en`): it keeps strings out of components and formats nothing itself; adding a language back is a second file. Files in `app/locales/`.

---

## 1. Strings

- **No hard-coded UI strings.** Every visible string, `aria-label`, page title, toast, confirm text and validation message is a key in `app/locales/en.json`. A key the code names but the file doesn't have fails `test/unit/locales.test.ts`.
- **Server error messages** are English; the app shows its own text for each `code` and falls back to the server's message ([D9](../decisions.md#d9-flat-error-body)).
- **What customers get** is the slip image (D35); its words are the artwork's and the values the owner typed.

### Key naming

```text
<feature>.<screen or part>.<element>
common.<group>.<element>          shared words: actions, states, errors
```

| Key | Text (en) |
|---|---|
| `orders.list.title` | Saved slips |
| `orders.new.save` | Save slip |
| `orders.order.nextSlip` | New slip |
| `customers.form.phone.label` | Phone |
| `common.actions.save` | Save changes |
| `common.states.loadError` | Couldn't load this. Try again. |

- Keys are `camelCase` parts joined by dots. Enum values keep their API spelling (`studio.html.samples.typical`), so code can build the key from the value.
- **One key per meaning, not per word.** "Saved slip" and "Saved slips" use different keys.
- **Use placeholders, never concatenation:** `"orders.order.title": "Slip No. {number}"`.
- Plurals use the module's plural syntax.
- Keys live in the file of the locale, grouped by feature. A feature's keys are removed with the feature.

## 2. Khmer that users type

- **Font:** a Khmer-capable font is set once in `tailwind.css` (Nuxt UI's `--font-sans`), with the Latin font first and a Khmer font next. **Inter** then **Noto Sans Khmer** (open license), downloaded at build and self-hosted by `@nuxt/fonts` so the CSP stays `font-src 'self'` (`nuxt.config.ts` → `fonts`: Khmer needs its own subset, [D21](../decisions.md#d21-contrast-and-fonts)).
- **Line height:** Khmer stacks consonants and vowel signs above and below the line. Use Tailwind's line heights (`leading-relaxed`, about 1.6) for Khmer body text; never a fixed height on a text container; never `leading-none` or `truncate` on Khmer text that can have subscripts (they get cut).
- **Line breaks:** Khmer has no spaces between words. Browsers break lines with dictionary data; long words can still overflow. Use `break-words` on text containers.
- **Size:** Khmer at `text-sm` is harder to read than Latin. If owners find it too small, the fix is a theme change (once, in `tailwind.css`), never per page.

## 3. Money, numbers and dates

All display goes through **shared formatters** in `app/utils/format.ts` (`formatDate`, `formatMoney`, `parseMoney`, `moneyInput`). ESLint forbids `Intl.*` and `toLocale*String` anywhere else in `app/`. The ones the server also needs (`formatMoney`, `formatDateTime`) live in `shared/format.ts`, re-exported by the app's file, so a slip and the screen write an amount the same way.

### Money (spec T12)

- Amounts are integers in **minor units** with a currency code: KHR = riel (no decimals), USD = cents.
- **Shown as** `13,500៛`, `$12.50`. `Intl` only groups the digits; the formatter sets the decimals from the currency and adds the symbol itself. Browsers' own currency output differs (Chromium writes `KHR 13,500` in Khmer, Node `13,500៛`), and the paper tickets write `13,500៛`.
- **Typed** as the plain amount (`13500` or `13,500` riel; `12.5` dollars): `parseMoney` refuses decimals for riel and a third decimal for dollars; the form sends minor units ([forms §1](./forms.md#1-where-the-forms-pieces-live)).
- **Digits:** Latin everywhere (`13,500`), as paper tickets and phone numbers write them.
- A shop has one currency (spec P7). A screen never mixes currencies.
- **Rounding** happens on the server (spec §16: weight totals rounded to whole riel or cents). The app never rounds money for storage.

### Weight (spec T13)

- Stored as grams; shown as kg with up to 2 decimals (`2.5 kg`, not `2.50 kg`). Typed as kg (`inputmode="decimal"`) and converted to grams in the form mapping ([forms §1](./forms.md#1-where-the-forms-pieces-live)).

### Dates and times (spec T14)

- Stored in UTC; **shown in `Asia/Phnom_Penh`** (the `shopTimeZone` runtime value), whatever the device's zone.
- Shown `en-GB` style: `16 Nov 2026, 15:40`. No screen formats a date by hand.
- Relative times ("2 hours ago", "ready 3 days") use `Intl.RelativeTimeFormat` through the same formatters.

### Phone numbers

- Stored as E.164 (`+85512345678`), normalized on the server (spec §6). Shown in Cambodian national format (`012 345 678`). Formatting uses `libphonenumber-js` (M2.2).

## 4. Labels

A form field's label in a template design is **one free-text label** (plan §5.3.1), shown to the owner as written. The platform writes it in the language the shop reads, Khmer included. A label is required to publish.
